# 05. エディタ設計

本システムの技術的中核。要件: FR-EDIT一式、FR-OBS(Obsidian互換)、FR-IMG(画像D&D)。

## 5.1 基本方針

1. **エディタはTiptap v2(ProseMirror)**。閲覧モードも同じスキーマで `editable: false` 描画し、閲覧/編集の見た目を一致させる。
2. **フロントマターはエディタに入れない**。`GET /api/docs` がフロントマターと本文を分離して返し、エディタは本文Markdownのみ扱う。タグ編集は専用UI(タグ入力欄)で行い、保存時にサーバーがフロントマターへ再結合する。往復変換の対象範囲を本文に限定し、破壊リスクを下げる(FR-EDIT-06)。
3. **往復変換の保証はテストで担保**。実ヴォルト由来のサンプル文書で「parse→serialize が冪等(2回目以降変化しない)」を検証する回帰テストを整備する。

## 5.2 Markdown ⇔ ProseMirror 変換

```
読み込み: Markdown(本文) ─ markdown-it + 独自拡張 ─▶ ProseMirrorドキュメント
保存:     ProseMirrorドキュメント ─ 独自シリアライザ ─▶ Markdown(本文)
```

- ベースに `tiptap-markdown`(markdown-it利用)を採用し、独自ノードの変換規則を追加する。
- 対応記法(FR-EDIT-02)と変換規則:

| 記法 | ProseMirrorノード | シリアライズ規則 |
|---|---|---|
| 見出し `#`〜`######` | heading | `#` 形式固定 |
| 太字/斜体/打消し | bold/italic/strike | `**` `*` `~~` |
| 箇条書き/番号付き | bulletList/orderedList | `-` / `1.` |
| チェックリスト | taskList/taskItem | `- [ ]` / `- [x]` |
| 表(GFM) | table | GFMパイプ表 |
| コードブロック | codeBlock(language属性) | フェンス ``` 言語名 |
| 引用 | blockquote | `>` |
| 水平線 | horizontalRule | `---` |
| リンク | link mark | `[text](url)` |
| 画像(標準) | image | `![alt](相対パス)` |

- **未知の記法の保全**: パースできないブロック(HTMLブロック等)は `rawBlock` ノード(等幅・グレー背景の編集可能テキスト)として保持し、シリアライズ時に原文をそのまま出力する。「読んだものは壊さない」を最優先とする。

## 5.3 Obsidian互換の独自拡張

### wikilink(FR-OBS-02)

- インラインノード `wikilink { target, alias }`。正規表現 `[[target]]` / `[[target|alias]]` をmarkdown-itインラインルールで認識。
- 表示: リンク風スタイル。クリックで `target` を解決し(`/api/tree` のタイトル索引から最短パス規則で一致)、該当文書へ遷移。未解決はグレー表示(遷移不可。リンク切れ検出 FR-LINK-03 の土台)。
- 入力: `[[` とタイプするとTiptap Suggestion による文書名補完ポップアップを表示(FR-LINK-01)。**候補は全文書からタイトル・パスの部分一致で最大200件**、↑↓/Enter/Escで操作、IME変換中は発火しない(`packages/client/src/editor/extensions/wikilink-suggestion.ts`)。`[[` の直前文字に関係なく発火する(`allowedPrefixes: null`)。コードブロック・インラインコード内では発火しない。`Ctrl/Cmd+Shift+K` で明示的に開く。カーソル直前に閉じていない `[[`(全角 `［［` も可、半角に正規化)があればそこからカーソルまでを絞り込み語として開く。無ければ `[[` を挿入(範囲選択中は選択テキストを絞り込み語にする)。Esc で閉じた後の再表示にも使う。Esc で閉じた後は、同じ範囲でも入力内容(絞り込み語)が変わると自動的に再表示される。ポップアップはドキュメントのスクロールで閉じず、位置を追従する。
- シリアライズ: 原文どおり `[[target]]` / `[[target|alias]]`。

### 埋め込み `![[...]]`(FR-OBS-03)

- ブロック/インラインノード `embed { target }`。画像拡張子(`png/jpg/jpeg/gif/svg/webp`)ならファイル名をサーバーの添付索引(`attachment_index`。02章2.2)で解決し `<img>` 表示する。PDF拡張子(`pdf`)は同じ添付索引解決で `<iframe>` 表示する(FR-IMG-04。issue #204)。
- 解決はサーバー1リクエストで完結する: `GET /api/embed?target=<file>&from=<docPath>`(`packages/client/src/lib/resolve-embed-src.ts`)。クライアント側での候補総当りは行わない。解決規則(サーバー側、Obsidianの「ヴォルト全体の名前索引」に相当):
  - `target` が `/` を含むパス指定のとき、ライブラリルートからの完全パスと一致する候補は最優先(Obsidian同等)。名前のみの指定ではこの規則は適用せず、下記の同フォルダ優先に従う。
  - 次に `target` にファイル名一致(大文字小文字を区別しない)、または `/` を含む場合はパス末尾一致。
  - 候補が複数あるときは ①文書と同じフォルダ ②文書フォルダとの共通祖先が深い方 ③パスの浅い方 ④辞書順、の優先度で1件に絞る。
- `target` は `file[#anchor][|幅]` または `file[#anchor][|幅x高さ]` の形を取り得る。`|幅`・`|幅x高さ` は `<img>`/`<iframe>` の `width`/`height` に反映する(PDFは未指定時 幅100%・高さ600)。`#anchor` は画像側では解決に使わないが、PDFでは`<iframe src>` の末尾に `#<anchor>` としてそのまま引き継ぐ(Obsidianの `#page=3` 等)。`|幅`/`幅x高さ`の形にならない `|別名` は解決・表示サイズに使わない(`parseEmbedTarget`)。
- 画像読み込みが失敗した場合(`onError`)は1回だけチップ表示(`![[target]]` 原文)に切り替える。PDFは`<iframe>`で`onError`が効かないため失敗検知は行わない(壊れていればブラウザ既定のPDFエラー表示になる)。
- 画像・PDF拡張子の判定は`isImageFile`/`isPdfFile`(`resolve-embed-src.ts`)に集約する。
- 画像・PDF以外(文書埋め込み等)は初期リリースではリンクとして表示(展開しない)。シリアライズは原文保持。

### 標準画像 `![alt](src)` の表示解決

- 相対パスは文書フォルダ基準で `..`/`.` を正規化(ルートより上には出ない)した上で `/api/files/<path>` に解決する(`resolveImageSrc`)。絶対URL(`http`/`https`/`data`)はそのまま使う。
- 読み込みに失敗したら、`src` のファイル名部分だけを埋め込みと同じ添付索引解決(`GET /api/embed`)にフォールバックする(`imageFallbackSrc`)。それも失敗したら壊れた画像アイコンのまま表示する。
- `src` がPDFの場合は`<iframe>`で表示する(issue #204)。`<iframe>`は`onError`が効かないため索引フォールバックは行わず、文書フォルダ相対の`/api/files/...`のみで解決する(それで解決できなければブラウザ既定のPDFエラー表示になる)。

### 画像の管理メニュー(FR-IMG-05・issue #199)

- 埋め込み画像(`![[...]]`)・標準画像(`![alt](src)`)のNodeView(`embed-view.tsx`・`image-view.tsx`)は、画像を `span.attachment-frame` で包み、右クリック(`onContextMenu`)またはホバー/フォーカスで現れる「⋯」ボタン(`button.attachment-menu-button`。`aria-haspopup="menu"`)からメニューを起動できる。ボタンは既定で `opacity:0; pointer-events:none` にし、ホバー/`:focus-visible`/`@media (hover: none)`(タッチ端末)でのみ `opacity:1; pointer-events:auto` にする(opacityだけ切り替えるとタッチ端末で「見えるが押せない」事故になるため必ず両方セットで切り替える)。絶対URL(`http`/`https`/`data`)の画像、および読み込みに失敗して原文チップ/壊れた画像アイコン表示になっている間はメニューを出さない。編集モード・閲覧モードのどちらでも有効(`editor.isEditable` で挙動を変えない)。
- NodeViewはDOM操作以外の状態を持たないため、`editor.storage.tsumiwikiDoc.openAttachmentMenu(req)`(`editor/doc-storage.ts` の `AttachmentMenuRequest`)を呼んで `<DocView>` に「このメニューを開いてほしい」と伝える。`req.target` は埋め込みなら `parseEmbedTarget(target).file`(サイズ/アンカー/別名は含まない)、標準画像なら `src` そのもの。
- `<DocView>` は `openAttachmentMenu` 受信時に `GET /api/attachments/resolve` で対象を解決し、成功したら `<ContextMenu>` を該当座標に表示する(未解決=404はメニューを出さずトースト表示)。メニュー項目は「名前を変更」「パスをコピー」「削除」。
  - 「名前を変更」: `<PromptDialog>` → `POST /api/attachments/rename`。レスポンスの `rewrittenDocs[].replacements`(その文書で実際に書き換えた `target→新target` の対応。trim済み・`|alias`・`#anchor`・`?query`・`"title"` を含まない)に**厳密一致**するノードだけをProseMirrorトランザクションで書き換える(サイズ/アンカー/フォルダ部分は保持)。basenameだけの一致では書き換えない(同名で別実体の添付を誤って書き換えないため)。現在文書が `rewrittenDocs` に含まれていなければエディタには一切触らない。
    書き換えはサーバー側で既にファイルを書き換え済みのため未保存編集として扱わない。`useEditingSession` に `syncBody(body)`(`contentRef` だけ更新し `dirty` は変えない)を追加し、`onUpdate` 側でこの1回だけ `updateBody` の代わりに `syncBody` を呼ぶことで実現している(こうしないと、リネーム後すでにdirtyだった編集をそのまま保存したときに旧ファイル名が復活してリンク切れになる)。
    `rewrittenDocs` に現在文書が含まれていれば React Query キャッシュ(`docQueryKey`)の `updatedAt` を更新し(次回保存が旧 `baseUpdatedAt` により競合しないように)、実際に置換が起きた場合だけ `body` も最新のMarkdownで更新する(置換が無ければ `body` は触らない)。他に開いているタブの文書は `invalidateQueries` で無効化する。
  - 「削除」: メニュー選択と同時に `<ConfirmDialog>` を「参照を確認しています…」で先に表示し(確定ボタンは無効)、`GET /api/attachments/references` の結果が届いたら本文(他文書からの参照があれば件数を明記)と確定ボタンの有効化を追随させる。確定で `DELETE /api/attachments`。エディタ内のノードは書き換えない(Obsidianと同じ。次回表示時に404→チップ/壊れた画像アイコンになる)。
  - 「パスをコピー」: 解決済みパスを `navigator.clipboard.writeText` でコピーする。
- **削除/リネーム後の再表示(実機確認対応)**: ブラウザは一度読み込みに成功した `<img src>` を同じURLでは再取得しないため、削除・リネーム操作をしても対象を表示中の他のNodeView(別タブ・ペイン、あるいはリネーム対象外の同名添付)の `<img>` が古いまま残ることがある。`<DocView>` は削除・リネーム成功時に `window` へ `tsumiwiki:attachment-changed`(`detail.names`: 変化したbasename一覧。削除ならその名前、リネームなら旧名)をdispatchし(`lib/attachment-events.ts`)、各NodeViewは `useEffect` でこれを購読して自分のbasenameが含まれていれば再取得用のカウンタを増やし、`src` に `?v=<n>`/`&v=<n>`(`withCacheBuster`)を付けて強制的に再取得する。同時に失敗チップ/壊れた画像状態もリセットする(再取得が実際に失敗すれば改めてその状態に遷移する)。basenameだけで判定するため、同名で別実体の添付も無関係に再取得されることがあるが、再取得自体は副作用が無く実害はない。
- **Obsidian互換の限界**: bare wikilink記法 `![[name.png]]`(フォルダ指定なし)はリネーム後も「同フォルダ優先」等の索引解決規則(本章「埋め込み `![[...]]`」節)にそのまま従うため、リネームで空いた名前に別の実体が新たに解決されるとその画像に切り替わって見えることがある(Obsidian本体と同じ挙動で、tsumiwiki固有の不具合ではない)。`%20` 等URLエンコードされたMarkdownリンク(サーバーはURLデコードしない設計。A-3節)はリネームの書き換え対象外になる。削除は参照を書き換えないため、削除した画像を含む文書は次に開いたとき(または上記イベントでの再取得時)に即チップ/壊れた画像アイコン表示になる。

### インラインタグ(FR-OBS-06)

- 編集中は装飾(Decoration)で `#タグ` をハイライト表示するのみ。ノード化しない(プレーンテキストのまま保存されるため往復安全)。
- タグの抽出・集計はサーバーのインデックスサービスが担当(02章2.3)。

### Mermaid(FR-EDIT-10)

- `codeBlock(language=mermaid)` にNodeViewを適用:
  - 閲覧モード: mermaid.jsでSVGレンダリング(`securityLevel: 'strict'`)。構文エラー時はエラーメッセージ+ソース表示。
  - 編集モード: フォーカス中はソース編集、フォーカスが外れるとプレビュー表示に戻る。
- シリアライズ: 通常のコードブロックとして原文出力。

### Dataviewブロック(FR-OBS-08)

- `codeBlock(language=dataview|dataviewjs)` は**実行せず**通常のコードブロック表示。専用NodeView不要。往復で原文保持されることをテスト対象に含める。

### 外部ファイルリンク(FR-LINK-02)

- `file://` スキームまたはUNCパス(`\\server\...`)のリンクは、閲覧時にリンク横へ「パスをコピー」ボタンを表示するNodeViewを適用。クリックによる直接遷移も妨げない(許可された環境向け)。

## 5.4 ツールバー(FR-EDIT-03)

```
[H1 H2 H3] [B I S] [インデント 戻す] [リスト 番号 チェック] [表] [コード 引用 区切り線] [リンク 画像] [Mermaid] [テンプレ適用]
```

- 各ボタンはTiptapコマンドを呼ぶ。現在のカーソル位置の状態をボタンのアクティブ表示に反映。
- 「画像/PDF」はファイル選択ダイアログ→添付アップロード(D&Dと同経路)。
- 「Mermaid」は空のmermaidコードブロックを挿入するテンプレートボタン(文書テンプレート機能とは無関係)。
- 「テンプレ適用」は `<TemplatePickerDialog mode='apply'>` を開き、選択したテンプレを **挿入**(カーソル位置)または **追記**(文書末尾)。1トランザクションで実行するため 1回の Undo で完全復帰する。`{{cursor}}` プレースホルダがあれば挿入後にその位置へカーソルを移動。

## 5.5 画像・PDFの挿入経路(FR-IMG-01/02/04)

```
D&D / ペースト / ツールバー
  → POST /api/attachments (multipart, docPath)
  → サーバー: 文書と同フォルダに保存+コミット
      画像: image-YYYYMMDDHHmmss.png 形式(自動命名)
      PDF : 元ファイル名のbasenameを尊重(危険文字は_に置換。Obsidian互換)
      いずれも衝突時は -2, -3 ... を付加
  → 応答のファイル名で ![[ファイル名]] ノードを挿入
```

D&D/ペースト対象のファイル種別判定(`isAttachmentFile`。`DocView.tsx`)は `image/*` MIME または `application/pdf` MIMEのファイルを受け付ける。

- アップロード中はプレースホルダ表示。失敗時はノードを除去しトースト表示。
- 対応形式: png / jpg / jpeg / gif / svg / webp。サイズ上限20MB(設定可)。

## 5.6 日本語入力(IME)対応(FR-EDIT-05)

- ProseMirrorのcomposition対応に準拠。追加規則:
  - 入力規則(`#` →見出し等のInput Rules)・サジェスト発火は `compositionend` 後にのみ評価。
  - ショートカット処理は `event.isComposing` 中は無視。
- 受け入れ確認: macOS(ライブ変換オン)+ Windows(MS-IME)で、変換中文字列の分断・確定取り消し・wikilink補完の挙動を手動テストする(検証項目リストを実装時に作成)。

## 5.7 往復変換テスト(FR-EDIT-06の担保)

- `packages/client/src/editor/__tests__/roundtrip/` にサンプルMarkdown(実ヴォルトから抜粋・匿名化)を配置。
- テスト: `serialize(parse(md))` が `md` と一致(初回は正規化差分を許容し、2回目 `serialize(parse(x)) === x` の冪等性を必須とする)。
- CI(GitHub Actions)で常時実行。対応記法を追加するたびにサンプルを追加する。

## 5.8 テンプレート変数の展開

テンプレート機能(03章 `/api/templates/*`)とデイリーノート機能(03章 `/api/daily-notes/today`)で使う変数展開ユーティリティは、サーバー/クライアント共通の `packages/shared/src/template-vars.ts` に実装する。

| 変数 | 説明 |
|---|---|
| `{{date}}` / `{{date:FMT}}` | 現在日付。既定 `YYYY-MM-DD` |
| `{{time}}` / `{{time:FMT}}` | 現在時刻。既定 `HH:mm` |
| `{{year}}` `{{month}}` `{{day}}` `{{hour}}` `{{minute}}` | 個別コンポーネント |
| `{{title}}` | 文書のタイトル(拡張子なしのファイル名) |
| `{{user}}` | 現在のユーザー表示名 |
| `{{cursor}}` | 適用後のカーソル位置マーカー(サーバー側は空文字にせず残す。クライアントで位置決めに使う。ファイル名パターンや `stripCursor:true` 指定時は空文字に展開) |

日付フォーマットトークン: `YYYY / YY / MM / DD / HH / mm / ss / aaaa(月曜日) / aaa(月) / dddd(Monday) / ddd(Mon)`。曜日トークンは長い順に置換し `aaaa` の中の `aa` が先食いされる事故を防ぐ。未知の変数はそのまま残す(タイポでも情報が消えない)。
